# Qwen3-ASR-1.7B 8-bit 窗口缓存实测

2026-10-03，在 Apple M4 / 16 GB macOS 上测试。结论：此机的录播窗口吞吐足以支持 2× 前瞻识别，值得继续接入；识别准确率、逐句时间对齐及浏览器链路尚未验收。当前扩展仍使用 Whisper 和平台字幕，本实验不修改现有字幕选项。

模型采用 [mlx-community 的 Qwen3-ASR-1.7B-8bit](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-8bit)，固定 revision `a8379a2e2f9e313c9292cdf1af4055ab56d50d55`。运行时为 [mlx-qwen3-asr 0.4.4](https://github.com/moona3k/mlx-qwen3-asr)、MLX 0.32.3、Python 3.13。实际加载后的量化模块 bits 集合为 `{8}`；权重文件 2,463,307,541 字节，不下载额外对齐模型。

## 测量结果

使用老师授权的数值算法课程片段，原视频 10:00–40:00，单声道 16 kHz PCM16 WAV。连续处理 90 个 20 秒窗口，每窗口前后附带 2 秒上下文，片段边缘截断；中文解码、最大输出 512 token，并提供本课程的数学术语提示。首次遍历没有命中窗口缓存。

| 指标 | 实测 |
| --- | ---: |
| 有效音频时长（不重复计算上下文） | 1800 秒 |
| 90 窗口处理总耗时 | 176.58 秒 |
| RTF（处理时间 / 音频时间） | 0.0981 |
| 新建 Session 加载模型 | 0.57 秒 |
| 首窗准备好（含导入、内容摘要及模型加载） | 3.51 秒 |
| 模型加载后的窗口耗时中位数 | 2.01 秒 |
| 模型加载后的最慢窗口 | 2.83 秒 |
| MLX 峰值 GPU 分配 | 3.01 GiB |
| 同进程第二遍单窗读取最大值 | 0.55 毫秒 |
| 新进程复用全部 90 窗口 | 90/90 命中，无模型加载 |
| 新进程读取全部窗口文件总耗时 | 14.72 毫秒 |
| 新进程首遍单窗读取最大值 | 2.46 毫秒 |

首窗耗时不包含首次下载或 Python 解释器启动；模型文件可能已在系统文件缓存中。GPU 指标不是整机内存或进程 RSS。新进程缓存回访仍需要约 1.06 秒的导入和内容摘要初始化，不能把单窗读取时间说成整个启动时间。

使用实测窗口耗时模拟：首窗准备好后开始播放，顺序推理，最多允许 100 秒原视频前瞻；1×、1.5×、2× 的后续窗口都没有错过播放期限。2× 时每个 20 秒窗口可用 10 秒墙钟时间，本样本最慢约 2.83 秒，存在明显余量。模拟没有包含远程视频下载、其他应用争用 GPU、真实播放器 seek/暂停和字幕渲染。

另外，不提供关键词的 100 秒 / 5 窗口试跑也全部正常返回，处理约 10.67 秒。关键词是可选提示，不能保证修正术语，也没有依据此小样本判断关键词对准确率的总体影响。

## 本次发现的限制

- 抽查存在连贯的数学讲解，同时仍有口语重复、术语误识及重叠窗口重复。没有人工逐字标注，不报告 CER，不声称比 Whisper 准确。
- 模型输出是窗口文本，没有逐句/逐字时间戳；不能把整段文字在视频上显示 20 秒当作字幕同步已完成。接入前需时间对齐、边界去重及回归验证。
- 将 24 秒纯数字静音直接交给模型，即便有数学术语提示，仍返回了非空文本；没有截断。缓存层因此增加纯数字静音保护（振幅不超过 1 LSB），直接返回空文本。该保护不等于真实教室 VAD，背景噪声和停顿仍需语音检测和幻觉过滤。
- 上表吞吐在加入静音保护前测量；保护的跳过模型、缓存空文本行为由单元测试验证。真实片段的完整准确率及教室停顿行为尚未验收。
- 录播预取需要播放器前方的音频可读。此实验使用已获授权的本地片段，不证明 FFmpeg 能下载所有课程。直播无法预取尚未发生的内容。
