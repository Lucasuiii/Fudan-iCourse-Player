# Qwen3-ASR-1.7B：未量化原版与 8-bit 对比

2026-10-03，在 Apple M4 / 16 GB macOS 上完成对比。按用户选择，**保留未量化 BF16 原版**：原版处理每个 20 秒窗口最慢约 4.54 秒，2× 播放每窗有 10 秒墙钟预算，100 秒前瞻调度模拟没有迟到窗口，具备本机录播缓存字幕的吞吐余量。

8-bit 更快、更省内存，但两者术语识别互有优势。原版不保证整体更准确；这里遵循用户保留原版的选择。恢复原版并验证后，清理 8-bit 权重及其缓存，保留小体积私有对比记录。当前扩展尚未接入 Qwen，真实浏览器的 2× 显示、逐句对齐和边界去重尚未验收。

## 公平比较条件

使用老师授权的数值算法课程片段：原视频 10:00–40:00，单声道 16 kHz PCM16 WAV。两套模型分别启动独立进程，连续处理相同的 90 个 20 秒窗口，每窗前后各带 2 秒上下文，边缘裁切。两者使用相同的课程数学术语、中文解码、512 输出 token 上限、MLX 后端及 BF16 计算精度，首次遍历均未命中缓存。

- [8-bit 权重](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-8bit)：revision `a8379a2e2f9e313c9292cdf1af4055ab56d50d55`，权重文件 2,463,307,541 字节。
- [未量化 BF16 权重](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-bf16)：revision `e1f6c266914abc5a46e8756e02580f834a6cf8a7`，权重文件 4,076,186,653 字节。这是官方原版权重的 MLX 格式转换，未使用官方 CUDA 推理后端。
- 实测运行时：[mlx-qwen3-asr 0.4.4](https://github.com/moona3k/mlx-qwen3-asr)、MLX 0.32.3、Python 3.13。加载后校验量化模块：8-bit 的 bits 集合为 `{8}`，原版没有量化模块，解码器权重为 BF16。
- 配置核对：结构配置的差异只有量化项；分词器配置、词表、merges 和音频预处理配置逐字节一致。

8-bit 指权重压缩，BF16 计算精度指运行时浮点张量；本次两者都以 BF16 计算，避免把计算精度或推理实现的差异误当作量化影响。

## 实测性能

| 指标 | 8-bit（对照） | 未量化 BF16（保留） |
| --- | ---: | ---: |
| 有效音频时长，不重复计算上下文 | 1800 秒 | 1800 秒 |
| 90 窗口处理总耗时 | 176.21 秒 | 273.68 秒 |
| RTF，处理时间 / 音频时间 | 0.0979 | 0.1520 |
| 新建 Session 加载模型 | 0.59 秒 | 1.02 秒 |
| 首窗准备好，含导入、内容摘要及模型加载 | 4.49 秒 | 5.86 秒 |
| 模型加载后的窗口耗时中位数 | 1.98 秒 | 3.05 秒 |
| 模型加载后的最慢窗口 | 2.64 秒 | 4.54 秒 |
| MLX 峰值 GPU 分配 | 2.72 GiB | 4.10 GiB |
| 同进程第二遍单窗缓存读取最大值 | 0.80 毫秒 | 0.30 毫秒 |
| 100 秒前瞻、2× 播放调度模拟的迟到窗口数 | 0 | 0 |

缓存读取都是毫秒级文件操作，其小幅差异没有足够依据作为模型选择指标。首窗耗时不含首次下载或 Python 解释器启动，系统文件缓存可能已经热；GPU 指标不是整机内存或进程 RSS。调度模拟使用实测耗时，首窗准备好后开始播放，不等于浏览器验收，也未计入远程下载和其他 GPU 任务竞争。

此前 8-bit 新进程缓存回访为 90/90 命中；原版恢复后，以默认配置从新缓存处理 60 秒 / 3 窗口，用时 9.64 秒，确认加载无量化模块、BF16 权重，随后 3/3 命中缓存，最大读取耗时 0.18 毫秒。8-bit 权重和旧缓存已清理约 2.47 GB。

## 识别结果与选择依据

- 90 个窗口中，60 个原始文本完全一致；忽略标点、空格和英文大小写后，72 个完全一致。归一化仍保留负号、运算符及数字间的小数点，避免掩盖数学内容差异。
- 其余 18 个窗口总计 50 次归一化字符编辑，相对 BF16 的 7382 个归一化字符，**两模型文本差异约 0.677%**。这不是 CER、准确率或人工字幕对照结果，且窗口文本含重复上下文。
- 检查全部有内容分歧的窗口，主要变化是口语词、措辞及零星术语/同音字。两者均有优势案例：原版有一处正确识别了 Givens，8-bit 在另外的位置正确识别了 Householder 和 Givens；原版也出现了数学同音字退化。没有看到原版持续优于 8-bit 的趋势。
- 三个明确无语音的 24 秒控制输入（数字静音、固定种子的低幅白噪声、440 Hz 单频音），绕过缓存静音保护后，两模型均为 **3/3 非空输出**，均未截断。提高权重精度没有解决这些控制输入上的误生成。

没有人工逐字标注，因此不宣称 8-bit 的真实课堂准确率更高。原版也有足够的 2× 处理余量，并在部分术语位置表现更好；当前按用户选择以原版 BF16 为默认。
